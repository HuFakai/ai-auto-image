# 阶段 0：工程基础与技术验证 — 实施计划

按 docs/phases/00-foundation-and-validation.md + docs/04-ai-image-framework-solution.md 实施。用户未选择问答项，采用以下默认决策（可随时调整）：
- **Mock 开发，最后真实验证**：全部功能与 CI 用 Mock Provider；交付 `scripts/verify-openai.ts`、`verify-xai.ts`，若 `.env` 已有密钥则最后执行真实验证并出报告。
- **最小演示 Studio**（frontend-design skill 质量标准）：单页工作台（创建→实时进度→结果画廊）+ 运行历史 + /api/health。不做阶段 1 编辑器。
- **视觉方向：暗房工作室**——近黑底（#0E0E10 系）+ 琥珀点缀、宋体系大标题（Noto Serif SC）+ 无衬线正文、卡片如胶片帧逐张点亮；拒绝模板化 AI 风。
- **技术选型**：Node 24 + pnpm + Turborepo；Next.js App Router + Tailwind v4（阶段 0 自绘组件，不引 shadcn）；Drizzle ORM + better-sqlite3（WAL）；Vitest。

## 1. Monorepo 脚手架
```
apps/web/                 Next.js Studio + API
packages/  shared-schemas  ai-core  provider-openai  provider-xai
           provider-compatible  workflow-engine  render-engine
           storage  config
infra/     Dockerfile  docker-compose.yml
fixtures/  inputs/  expected/
docs/adr/  scripts/
```
TypeScript strict、ESLint+Prettier、统一 tsconfig（packages/config）、Conventional Commits、`.env.example`（不含真实 Key）。`content-engine/quality-engine/platform-adapters` 留到阶段 1 建目录。

## 2. shared-schemas（Zod）
ContentBrief、Storyboard、SlidePlan、TextRenderingMode（native|deterministic|auto_fallback）、GenerationConcurrency、ProviderRouteConfig、GeneratedImage、ModelUsage、8 类错误枚举、Job/Run 状态枚举。所有 LLM 结构化输出经 Zod 校验，失败允许一次带错误信息的修复调用（doc00 §4）。

## 3. ai-core
- 接口：`TextModel` / `ImageModel` / `VisualQualityModel`，返回统一领域对象（含 providerRequestId、usage）。
- **多路由回退** `withModelFallbacks`：preferred+fallbacks 逐 attempt，全败抛 `ModelRouteExhaustedError(attempts[])`；每次尝试写 `provider_attempts`（借鉴视频项目 llm_service，TS 重写）。
- 错误归一化 8 类（authentication/rate_limit/content_policy/invalid_request/timeout/provider_unavailable/download_failed/unknown）；瞬态码 {429,500,502,503,504} 指数退避 + Retry-After。
- **双信号量并发管理**：imageApi 与 postprocess 分开；effective = min(requested, serverMax, providerMax)；429 自动降并发；流式写盘防内存峰值（env：`IMAGE_GENERATION_CONCURRENCY_DEFAULT=1/_MAX=4`、`IMAGE_POSTPROCESS_CONCURRENCY_MAX=1`）。
- usage/cost 聚合（读 response.usage，视频项目无此能力，属新增）。

## 4. Providers（3 + mock）
- **openai**：chat/completions 文本 + images/generations/edits，URL/Base64 归一化。
- **xai**：OpenAI SDK + `base_url=https://api.x.ai/v1`；`/v1/images/*`；request-id 持久化；临时 URL 立即转存；读 usage。
- **compatible**：自定义 baseUrl/headers/model，能力显式配置不猜测，独立 Response Extractor。
- **mock**：可注入延迟/错误/图片，供测试与 CI。
- 能力表声明支持的模型，默认主力 `grok-imagine-image-2.0`、兜底 `gpt-image-2`。

## 5. storage
better-sqlite3（WAL、foreign_keys、busy_timeout）；drizzle-kit 迁移 SQL 入版本控制 + 种子数据。10 张表：projects、workflow_runs、node_runs、prompt_versions、assets、asset_relations、provider_attempts、provider_usages、jobs、job_events。Repository 接口隔离 SQLite 专属行为；文件资产仓 `.part` 原子写 + rename + 魔数校验。

## 6. workflow-engine
- Job 状态机 queued→running→succeeded｜retry_waiting→running｜needs_review｜cancelled｜failed；租约字段+心跳+超时回收（先持久化终态再取消）；attempts/recoveries 计数；幂等键复用；重启恢复（启动扫描未完成 job 重新入队）。
- RunSnapshot 冻结 provider/prompt/模板/并发配置。
- Spike DAG：parse-input → generate-brief → generate-storyboard → generate-images（按并发并行）→ [render-slides 仅确定性模式] → package-export。
- 单页失败仅重试该页。Brief/Storyboard 节点内置 prompt 模板（阶段 1 迁往 content-engine）。

## 7. render-engine
- 统一 `Renderer` 接口。
- **NativeAssetProcessor（默认）**：流式下载→原子落盘→魔数/尺寸校验→Asset 登记→可选轻压缩；不做文字合成。
- **DeterministicRenderer（默认关闭）**：封面/正文/总结 3 张知识卡片，Satori+Sharp，1242×1656，中文字体 Noto Sans SC（OFL，入库 assets/fonts），文字溢出检测，模板 SHA-256 指纹 + 相同输入可复现。

## 8. apps/web（Next.js App Router + Tailwind v4）
- 页面：Studio 工作台（输入主题/Recipe 固定知识卡片/比例/并发/文字模式 → 发起）+ 运行详情（节点进度、逐页画廊点亮、费用）+ 运行历史；`/api/health`。
- 数据通道：SSR 首屏 + 自适应轮询（活跃 3s/空闲 15s，借鉴 studio 模式；SSE 留阶段 1）。
- API 路由：POST/GET /api/runs、GET /api/runs/:id、POST /api/runs/:id/cancel、GET /api/health；返回 requested 与 effective 并发。
- 进程内 Job Runner 经 `instrumentation.ts` 随 Next 启动。
- Provider Key 本轮走 `.env`；设置页延后阶段 1。

## 9. infra
多阶段 Dockerfile（standalone、无 Chromium/Playwright、非 root）；docker-compose 单容器 + `/data/db`、`/data/assets`、`/data/exports` 持久卷 + 健康检查 + 内存限制 + 并发环境变量。

## 10. 测试、fixtures、ADR、验证脚本
- 单测：schema 校验、请求/响应归一化、错误映射、job 状态转换、并发 min()、成本计算、溢出检测。
- 集成（mock）：全流程、**重启恢复**（插 running job → 重启 → 续跑）、单页重试、资产落盘。
- 视觉快照：pixelmatch 确定性三卡。
- fixtures：3 个输入样例（中文知识主题为主）。
- ADR×5：模型层、SQLite 作业、双模式渲染器、持久卷布局、中期迁移策略。
- `scripts/verify-{openai,xai}.ts`：真实调用 → Storyboard 校验 → 出图 → 转存 → 报告。

## 实施顺序
1 脚手架 → 2 shared-schemas → 3 storage → 4 ai-core+mock → 5 三 provider → 6 workflow-engine → 7 render-engine → 8 apps/web → 9 infra → 10 测试/ADR/验证收尾。每步保持 lint+typecheck+test 全绿。

## 验收对照（doc00 §11）
docker compose up 可启动且重启数据留存；空闲 ≤250MB、单页合成峰值 ≤700MB（生产构建基准）；镜像无 Chromium/Playwright；默认并发 1 不可突破上限；Mock 全流程 CI 稳定；两 Provider 产出同 Schema Storyboard（真实验证脚本）；图片均转存 `/data/assets`；中文字体正确渲染；两模式完成同一套三页样例；单页失败不重跑整套；日志无 Key/Cookie。
