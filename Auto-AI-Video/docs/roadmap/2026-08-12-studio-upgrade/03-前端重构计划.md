# 03｜前端重构计划：Production Desk

## 技能选择与设计结论

本计划使用：

- `frontend-design`：确定鲜明、非模板化的产品视觉和交互方向；
- `ui-ux-pro-max`：校验视频 SaaS、实时仪表盘、中文字体、状态反馈、响应式和无障碍规则。

实施阶段再按需使用 `vercel:nextjs`、`vercel:shadcn`、`vercel:react-best-practices` 和 `vercel:verification`，分别约束框架、组件、React 性能和浏览器验收。

## 为什么不继续堆 Streamlit

现有 Streamlit UI 约 6994 行，已出现以下结构性问题：

- 页面、状态和业务逻辑混在大型 Python 文件中；
- 长任务依赖轮询和 Session State，难以表达持久队列和多任务实时状态；
- 频道、项目、分镜、审核、排期等复杂信息架构难以扩展；
- 组件化、路由、表格筛选、局部刷新和前端测试能力有限；
- UI 当前仍直接初始化核心服务，控制面与执行面没有完全分离。

FastAPI 继续做唯一业务入口，Next.js + TypeScript Studio 已完成替换；Streamlit 已移除。

## 技术方案

- Next.js App Router + TypeScript；
- Tailwind CSS + CSS Variables 维护设计令牌；
- shadcn/ui 只作为无障碍基础件，视觉层全部按本项目定制；
- TanStack Query 管理服务端数据、缓存和 mutation；
- SSE 接收任务与 Runner 事件，断线后以 REST 状态补偿；
- Zod 校验 API 数据和频道表单；
- React Hook Form 处理复杂配置；
- Playwright 做关键流程 E2E；
- 图表使用轻量库，仪表盘不加载重型视频编辑依赖；
- 视频、图表、分镜编辑器按路由动态加载。

前端不得直接读取 SQLite、YAML、output 或本地密钥；所有访问都经过 FastAPI。

## 视觉方向

名称：`Production Desk / 生产台`

风格：编辑部工作台 + 工业控制室，采用 Swiss 式网格和内容优先的深色界面，不使用常见紫色渐变 AI 风格。

建议设计令牌：

- 背景：墨黑 `#0B0D0C`；
- 面板：炭灰 `#151816`；
- 主文字：暖白 `#F2EFE7`；
- 次文字：灰绿 `#9BA39B`；
- 唯一品牌强调：信号黄绿 `#C8F04B`；
- 状态：成功绿、等待蓝、警告琥珀、失败珊瑚红；
- 正文：Noto Sans SC；数据/ID/时长：Fira Code；
- 8px 间距系统，明显但克制的 1px 边框；
- 动效只用于队列流动、状态变化和页面入场，并支持 `prefers-reduced-motion`。

最有辨识度的组件是“频道生产轨道”：每个频道是一条横向流水线，同时展示库存水位、在途任务、今日目标和下一补产动作。

## 信息架构

```text
总览 Overview
├── 频道轨道、产量、库存、失败和系统健康
频道 Channels
├── 配方、选题池、产量、模型、声音、模板、质量规则
创作 Create
├── 自动驾驶、智能协作、批量导入、测试样片
队列 Queue
├── 全部任务、运行时间线、日志、重试、取消
成片 Library
├── 预览、筛选、审核、版本、下载、修改
日历 Calendar
├── 已通过内容、平台排期、发布状态
数据 Insights
├── 产能、成功率、时长、内容表现
设置 Settings
└── Grok、TTS、存储、系统健康、密钥测试
```

全局右侧抽屉为 AI 制片助手，但不抢占主界面。

## 页面规格

### 总览

- 顶部只显示 API、Runner、Grok、磁盘四个健康指标；
- 主区显示频道生产轨道，不用一排同质 KPI 卡片；
- 下方为最近成片和需要处理的问题；
- 重要状态不能只靠颜色，必须有文字和图标。

### 频道详情

- 左侧为频道身份、提示词、种子和品牌配方；
- 中间为生产水位与最近选题；
- 右侧为测试样片和预检结果；
- 高级参数折叠，默认只暴露产量、风格、声音和模型；
- 保存、测试、启停是独立动作，避免误操作。

### 队列

- 默认按“需要注意 → 运行中 → 等待 → 已完成”排序；
- 支持频道、状态、日期、失败类型筛选；
- 行展开显示场景级时间线，不跳转也能判断卡点；
- retry/cancel 有明确 loading、成功和错误反馈，防止重复点击。

### 成片与审核

- 使用适合 9:16 的海报网格，不用文件表格作为默认视图；
- hover 只显示播放和摘要，不做导致布局跳动的缩放；
- 详情页左侧视频，右侧脚本/分镜/版本/质量报告；
- 键盘快捷键支持通过、驳回、上一条、下一条；
- 修改意见可直接创建新 Revision。

### 分镜工作台

- 不是复杂时间线：以场景卡片为主；
- 每卡包含旁白、提示词、缩略图、音频、时长和锁定状态；
- 支持重排、拆分、合并和单镜重做；
- 底部固定显示本次修改影响的场景数、预计调用和执行按钮。

## 后端 API 缺口

前端开工前至少补充：

```text
GET    /api/production/summary
GET    /api/production/jobs
GET    /api/production/jobs/{id}
POST   /api/production/jobs/{id}/approve
POST   /api/production/jobs/{id}/reject
POST   /api/production/jobs/{id}/retry
GET    /api/channels
POST   /api/channels
PATCH  /api/channels/{id}
POST   /api/channels/{id}/test
POST   /api/channels/{id}/pause
GET    /api/library/videos
GET    /api/models
POST   /api/models/{provider}/test
GET    /api/events                 # SSE
```

配置 API 返回的密钥必须始终掩码，写入时不能通过日志或任务记录泄露。

## 迁移阶段

当前进度：F0—F5 已完成，包括生成前分镜确认、项目/Revision/Scene、场景卡编辑、单镜重做、逐镜头版本差异、版本回退、质量报告、AI 制片助手、批量审核与队列操作。Streamlit 已移除。

### F0：设计和 API 契约

- 建立 OpenAPI 类型生成；
- 做总览、频道、队列、成片四页高保真静态原型；
- 建立设计令牌、状态枚举和响应式断点；
- 用真实任务数据，不使用与项目无关的占位卡片。

### F1：只读控制台

- 总览、频道、队列、成片可查看；
- SSE 任务进度；
- 健康检查和错误态；
- 与 CLI `status`、任务 JSON、实际 output 对照。

### F2：安全操作

- 创建测试样片、暂停频道、重试、取消、审核；
- 表单预检、确认弹窗、操作审计；
- 所有 mutation 有 loading 和幂等保护。

### F3：分镜与版本

- 项目/Revision/Scene 模型；
- 场景卡编辑、单镜重做、版本对比和回退；
- 质量报告。

### F4：日历与发布

- 内容日历、平台文案、发布适配器和数据面板；
- AI 制片助手接入受限工具。

### F5：移除 Streamlit

已完成：`web/`、Streamlit 依赖及旧启动方式均已删除。

## 前端验收

- 320、768、1024、1440 px 无横向溢出；
- 中文正文对比度至少 4.5:1；
- 所有按钮有键盘焦点，错误使用 `aria-live`/`role=alert`；
- 超过 300ms 的请求有 Skeleton 或进度反馈；
- mutation 期间禁用重复提交；
- 视频懒加载，列表滚动不会一次下载所有 MP4；
- SSE 断线可恢复；刷新页面不丢持久化任务状态；
- Playwright 覆盖：频道测试、提交、进度、失败重试、审核、下载。
