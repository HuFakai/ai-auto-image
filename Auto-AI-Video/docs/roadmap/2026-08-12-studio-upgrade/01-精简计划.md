# 01｜精简计划：收敛为 Grok-first 视频生产内核

## 目标

删除不再使用的 ComfyUI/RunningHub、数字人口播和动作迁移，同时保证以下主链路不变：

```text
频道选题 → Grok 文案/分镜 → Grok 视频 → Edge TTS → HTML/FFmpeg 合成
        → 持久化任务 → 成片库存 → 审核/发布
```

## 审计结论

- Streamlit Python 代码约 6994 行。
- `digital_human.py` 964 行、`action_transfer.py` 512 行、`digital_tts_config.py` 208 行；直接可移除 UI 共约 1684 行，占现有 UI 约 24%。
- `workflows/` 下有 29 个 RunningHub/SelfHost JSON，共约 116 KB。
- 纯 Comfy 后端候选至少包括：`comfy_base_service.py` 332 行、`image_analysis.py` 197 行、`video_analysis.py` 205 行。
- `MediaService` 不能直接删除：它当前同时承担 `api/...` 工作流向 `APIProviderMediaService` 的转发。
- `TTSService` 不能直接删除：需要保留其中的本地 Edge TTS，并去掉 Comfy 分支。
- `comfyui.image.prompt_prefix` 实际也被 Grok 直连链路使用，必须先迁移到新的 `media.image` 配置，不能连同 Comfy 配置一起丢弃。

## S0：建立删除前保护网

先增加契约测试，测试全部通过后才开始删除：

- 配置加载：旧 `config.yaml` 可迁移，新配置不包含 Comfy 字段；
- Edge TTS：指定 voice、speed、output_path 可生成音频；
- API Media：`api/grok/grok-imagine-image-quality` 和 `api/grok/grok-imagine-video` 路由正确；
- 完整异步任务：提交、进度、完成、文件下载；
- 重启恢复：复用 task_id、output 目录和 Grok request_id；
- Runner：读取三个频道、同步任务、库存达标后不重复补产；
- API 兼容：需要保留的旧字段有明确迁移期和弃用响应。

实施删除前记录：测试结果、`/health`、Runner `status`、一条完整成片的 ffprobe 信息。

## S1：先删除两条不用的产品流水线

删除：

- `web/pipelines/digital_human.py`；
- `web/pipelines/action_transfer.py`；
- `web/pipelines/__init__.py` 中的注册；
- 中英文 locale 中 `pipeline.digital_human`、`digital_human.*`、`pipeline.action_transfer`、`action_transfer.*`；
- API 媒体能力表里的 `digital_human`、`action_transfer` 适配标签；
- 仅被这两条流水线引用的素材校验、Session State 和帮助文案。

同时删除 `moviepy`，前提是再次确认仓库中已无其他导入。

验收：Streamlit 仍能打开；标准视频、图生视频、素材驱动三个入口正常；19 项现有测试和新增注册测试通过。

## S2：把媒体服务改成纯 API 门面

先重构，再删 Comfy：

1. 将 `MediaService` 改为轻量 `MediaService` 门面，或直接统一到 `APIProviderMediaService`。
2. 所有媒体模型统一使用 `api/{provider}/{model}` 标识。
3. 默认图片/视频模型迁移到：

   ```yaml
   media:
     image:
       default_workflow: "api/grok/grok-imagine-image-quality"
       prompt_prefix: "..."
     video:
       default_workflow: "api/grok/grok-imagine-video"
       prompt_prefix: "..."
   ```

4. 将 StandardPipeline、AssetBasedPipeline、FrameProcessor、API `/image/generate` 和现有 UI 调用统一改为纯 API 门面。
5. 将 `/api/resources/workflows/media` 替换为模型能力目录，例如 `/api/models/media`；响应包含 provider、model、image/video、比例、分辨率、输入模态和是否已配置。

验收：没有 Comfy 配置时，Grok 图片、Grok 视频、图生视频和完整成片仍成功。

## S3：把 TTS 收敛为 Edge TTS

- `TTSService` 不再继承 `ComfyBaseService`；
- 删除 workflow、runninghub_api_key、comfyui_url、ref_audio 和 inference_mode 分支；
- 根配置改成：

  ```yaml
  tts:
    provider: "edge"
    voice: "zh-CN-YunjianNeural"
    speed: 1.2
  ```

- API 请求使用 `voice`、`speed`，对旧 `voice_id` 暂时兼容一版；
- 删除 `/api/resources/workflows/tts`，增加 `/api/tts/voices`；
- 保留音频时长检测、重试和输出路径隔离。

验收：三个频道的现有 voice 配置能迁移，成片音轨存在、时长正确。

## S4：删除 Comfy 后端与工作流资产

删除候选：

- `pixelle_video/services/comfy_base_service.py`；
- `pixelle_video/services/image_analysis.py`；
- `pixelle_video/services/video_analysis.py`；
- `workflows/runninghub/`、`workflows/selfhost/`；
- Core 中的 ComfyKit import、实例、配置 hash、懒加载和 cleanup；
- `ComfyUIConfig`、`TTSComfyUIConfig` 及所有 RunningHub 字段；
- `web/components/digital_tts_config.py`；
- Settings、Style Config、Resources API 中的 Comfy/RunningHub 选择器；
- Docker、Windows 包装、README、FAQ、i18n 中的相关说明；
- `comfykit` 依赖和 NOTICE 条目。

素材分析只保留 `APIAssetAnalysisService`。如果 Grok 当前视觉契约不足，素材驱动入口应显示“未配置分析模型”，而不是静默回退到 Comfy。

## S5：第二批可选瘦身

在第一批稳定至少一个生产周期后再执行：

| 候选 | 建议 | 条件 |
|---|---|---|
| `fastmcp` | 删除 | 当前 Python 源码零引用 |
| `CustomPipeline` | 删除或移入 examples | 没有频道/API 使用 |
| 非 Grok 媒体供应商 | 先改 optional extra | 确认未来不需要供应商切换 |
| DashScope SDK、PyJWT、NumPy | 随供应商模块一起裁剪 | 全仓引用归零 |
| 双语旧 README/历史宣传内容 | 精简 | 保留安装、运行、架构、API 四类文档 |

不删除：OpenAI SDK（Grok 文本兼容接口仍使用）、Playwright、BeautifulSoup、FFmpeg、Edge TTS、HTTPX、SQLite 生产账本。

## 完成标准

- 代码和配置中搜索 `comfy|runninghub|digital_human|action_transfer`，除迁移说明外为零；
- `uv lock` 与最小安装成功；
- 单元/集成测试通过；
- 单条真实完整成片成功；
- API 重启后任务恢复成功；
- Runner 继续维持库存，且不会重复提交已存在任务；
- 本地密钥、数据库和 output 不进入 Git。
