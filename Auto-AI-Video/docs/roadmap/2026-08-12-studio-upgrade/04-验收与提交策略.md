# 04｜验收、提交与回滚策略

## 分支策略

当前可靠基线位于：

```text
codex/grok-provider-durable-jobs
```

实施时从该分支创建：

```text
refactor/grok-only-core
feat/production-control-api
feat/production-desk-web
```

计划文档可以留在当前分支；删除和重构不要与前端大改混在同一分支。

## 建议提交序列

每个提交都应可测试、可单独 revert：

```text
docs(plan): define slimming and studio upgrade roadmap
test(core): lock grok-only production contracts
refactor(ui): remove digital human and action transfer
refactor(media): introduce api-only media facade
refactor(tts): keep edge tts only
refactor(core): remove comfyui and runninghub support
chore(deps): prune workflow-only dependencies
docs(core): document grok-only setup
feat(api): expose production control plane
feat(web): scaffold production desk
feat(web): add channel and queue views
feat(web): add review library and safe mutations
```

不要把依赖锁文件、数千行删除和行为重构压进一个提交。

## 实施前快照

真正删除代码前：

1. 等待 `in_flight=0`；
2. 正常停止 Runner 和 API；
3. 记录当前 commit；
4. 备份 `config.yaml`、`data/production.db*`、任务存储和 `data/grok_jobs/`；
5. 不复制整个 `output/`，但记录一个已验证成片路径和 hash；
6. 确认备份目录不在 Git 工作树内。

任何删除都使用明确文件列表；不使用针对仓库根目录的递归删除命令。

## 每阶段测试门槛

### 静态检查

```bash
uv run ruff check <本阶段修改文件>
uv run pytest -q
```

上游仓库已有全库历史风格告警；精简阶段只要求修改范围无新增告警，再单独安排一次全库清理。

### API 冒烟

```bash
uv run python api/app.py --host 127.0.0.1 --port 18123
curl -fsS http://127.0.0.1:18123/health
```

随后提交一个单场景或最小场景的异步视频任务，确认：

- 状态从 pending → running → completed；
- 输出可通过 `/api/files/...` 下载；
- ffprobe 识别 H264 视频和 AAC 音频；
- 停止 API 后退出码为 0；
- 重启 API 不重复创建顶层任务。

### Runner 验收

- 先运行 `status`；
- 如果 ready 已达到目标，不运行 `once`；
- 需要测试补产时，临时使用独立测试频道和独立测试数据库；
- 测试后不修改正式 `production.db` 的 published 状态；
- 确认第二 Runner 只能进入 standby。

### 前端验收

- 使用真实 FastAPI，不在 UI 内直接调用生成核心；
- 测试空状态、健康、生成中、失败、重试、完成和断线恢复；
- 对照 CLI/SQLite 确认计数一致；
- Playwright 截图验证桌面和移动端；
- 键盘操作、对比度、错误播报通过。

## 回滚

- 行为问题优先 `git revert <commit>`，不使用 `git reset --hard`；
- 数据迁移必须有向前和向后脚本；
- 新旧配置至少保留一个版本的读取兼容；
- Next.js Studio 为唯一前端入口；
- 发布适配器默认 dry-run，直到审核和幂等验证完成。

## 最终完成定义

截至 2026-08-13，精简阶段、P0/F2、场景/Revision 版本化、生成前确认、单镜重做、版本差异、技术和内容质量门禁，以及 P2 Brand Kit / Recipe 不可变版本、任务快照和智能选题收件箱已达到对应条目；URL/RSS 内容源、向量语义去重、内容日历和真实平台发布仍属于 P2—P3 后续工作，不应被误报为已完成。

- 仓库不再安装或初始化 ComfyUI/RunningHub；
- 数字人口播和动作迁移不再出现在代码、API 和 UI；
- Grok + Edge TTS 主链路连续运行至少一个生产周期；
- 频道、队列、成片审核可在新前端完成；
- 任务、场景、版本和发布状态均可持久化恢复；
- 文档、示例配置、Docker/本地启动命令与实际代码一致；
- 所有提交保持本地可审查，用户确认后再推送远端。
