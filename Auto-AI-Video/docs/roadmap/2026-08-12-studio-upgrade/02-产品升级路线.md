# 02｜产品升级路线：从脚本 Runner 到智能视频生产台

## 产品定位

目标不是复制 Premiere，而是做一个面向批量短视频的“自主生产控制台”：用户设定频道、风格、产量和审核规则，系统持续选题、生成、检查和入库，并由人工控制生产决策。

## 市面产品启发

以下只采纳适合本项目的工作流，不照搬全部功能：

| 产品 | 官方能力 | 本项目应吸收的部分 |
|---|---|---|
| [invideo AI](https://help.invideo.io/en/articles/9382180-how-can-i-create-a-video-using-my-script) | 对话式 Agent 与一次生成两种模式 | “智能协作”和“自动驾驶”双入口 |
| [invideo Storyboards](https://help.invideo.io/en/articles/14754413-creating-storyboards-with-invideo) | 先锁定分镜、角色、灯光和艺术方向，再生成视频 | 生成前分镜预览、单镜重做、视觉一致性 |
| [Descript Underlord](https://help.descript.com/hc/en-us/articles/36803785502221-Underlord-beta-Your-AI-co-editor-in-Descript) | 项目内 AI 协作、批量编辑、历史与 Revert | 可解释的修改计划、版本历史、一键回退 |
| [OpusClip](https://www.opus.pro/calendar) | 内容日历、多平台排期、文案标签和发布分析 | 日历、发布队列、平台文案、数据闭环 |
| [Captions Batch Edit](https://captions.ai/help/guides/advanced/batch-edit) | 同一风格批量生成、异步并行、逐条快速审核 | 批次、品牌风格锁定、生成与审核并行 |
| [VEED](https://www.veed.io/) | Brand Kit、团队协作、素材库、发布 | 品牌套件、素材库和审核状态 |
| [Canva AI Video](https://www.canva.com/features/ai-video-generator/) | 生成后进入可视化编辑器继续调整 | 先快速生成，再按场景修订，而非全部重做 |

## P0：可观察、可控制的生产台

这是前端重构前必须补齐的后端控制面。

实施状态：2026-08-13 已完成本节的频道基础参数管理、生产队列安全操作、SSE、成片库、审核门禁和发布标记。场景级事件与失败原因自动归类随 P1 任务模型继续增强。

### 1. 频道管理

- 可视化创建/复制/启停频道；
- 设置选题策略、种子池、历史去重窗口；
- 设置每日目标、库存水位、并发、重试和熔断；
- 设置视频模型、场景数、配音、模板、BGM、提示词；
- 保存前执行预检，并提供“只生成一个测试样片”。

### 2. 生产队列

- 按频道和状态查看 planned/submitting/pending/running/ready/failed；
- 展示 Pixelle task、Grok request、当前场景和最近事件；
- 支持取消、同 ID 重试、暂停频道、恢复频道；
- 失败原因归类：配置、上游、超时、媒体、合成、磁盘；
- 用 SSE 推送进度，网络断开后可重新读取持久化状态。

### 3. 成片库与审核

- 竖屏海报式预览、频道/日期/状态筛选；
- ready 改为 `review_pending → approved/rejected`；
- 支持通过、驳回、写修改意见、下载、标记已发布；
- 展示题目、脚本、分镜、模型、时长、文件大小和任务版本。

## P1：生成前可规划，生成后可局部修改

实施状态：2026-08-13 已完成稳定实体、历史成片导入、不可覆盖 Revision、场景文本编辑/排序/拆分/合并/锁定、版本切换与回退，“完整/仅画面/仅配音”单镜生成，以及生成前分镜确认和逐镜头版本差异。

### 项目与版本模型

引入稳定实体：

```text
Channel → Project → Revision → Scene → Artifact
                    └→ Review → Publication
```

- Project 代表一个视频主题；
- Revision 代表一次完整修改版本；
- Scene 持久化旁白、视觉提示词、音频、视频和合成片段；
- Artifact 记录路径、hash、模型和生成参数；
- 修改单个场景只重做该场景及最终拼接，不重跑全部任务；
- 每次 Agent 修改先生成计划，用户确认后执行，可回退到旧 Revision。

### 分镜工作台

- 在昂贵的视频生成前先显示脚本和分镜卡片；
- 支持拖动排序、拆分、合并、锁定场景；
- 支持单独改旁白、视觉提示词、声音或时长；
- 支持“仅重做这个镜头”和“保持角色/风格重做”；
- 记录参考图和固定 style seed，提升系列一致性。

## P1：自动质量门禁

实施状态：2026-08-13 已完成文件、媒体轨、编码、竖屏分辨率、帧率、时长、音量、黑帧、冻结画面和字幕真实布局安全区检测；已完成通用禁用词、科普事实边界、心理诊断化/恐吓措辞、行动建议和 Grok 二次审校。质检失败会创建可回退草稿，并按配音、画面或仅合成的最小影响步骤自动修复，任务与计划可审计、可恢复。

成片完成后先进入质量检查，再进入审核：

- ffprobe：文件可播放、H264/AAC、分辨率、比例、帧率和时长；
- 音频：非静音、响度范围、无明显截断；
- 画面：黑帧、长时间冻结、字幕安全区、片尾完整；
- 内容：标题/主题近似去重、脚本长度、禁用词；
- 科普频道：让 Grok 对事实性和“事实/推测”表达进行二次审查；
- 心理学频道：检查诊断化措辞、恐吓式表达和行动建议；
- 自动门禁失败时只重做受影响步骤，并保留审计记录。

## P2：品牌套件与配方

实施状态：2026-08-13 已完成第一批基础能力。Brand Kit 与 Recipe 均使用不可变版本；频道绑定具体版本；任务创建时冻结完整配置快照并将品牌参数注入模板与默认声音。创作台已支持创建 V1、从当前版本发布新版本、查看版本数量及频道精确绑定。A/B 开头、批量替换和从成片保存模板留在后续增量。

- Brand Kit：Logo、颜色、字体、片头片尾、字幕样式、默认声音；
- Recipe：栏目提示词、场景结构、模板、模型参数、质量规则；
- Recipe 版本化；新任务绑定具体版本，旧成片可复现；
- 支持复制频道、A/B 两套开头、批量更换字幕/片尾；
- 允许从当前成片保存为新模板，而不是反复填写同一组参数。

## P2：选题与内容智能

实施状态：2026-08-13 已完成第三批内容智能能力。除 Markdown/主题池外，创作台可持久化接入公开 URL、RSS 和 Atom；Runner 按来源周期提交可恢复的异步采集任务，安全抓取、解析、内容指纹去重后由 Grok 生成候选。每条候选保存概念词和 384 维归一化语义哈希向量，重复判断综合语义向量与字面相似度。候选同时保存对照标题与 clarity、curiosity、contrast、action 标题假设，人工选中的标题才随候选进入生产。来源可启停、手动采集，并展示素材总数、本轮新增、候选数量、下次时间和错误。

- 支持 URL、Markdown、RSS、Atom 或主题池作为内容来源；
- 选题前做近期历史、关键词和语义去重；
- 生成标题、封面文案、平台描述和标签的多个候选；
- 为每条内容计算“可解释评分”：新颖度、具体度、可信度、系列匹配度；
- 提供选题收件箱，允许人工钉住、延后或丢弃；
- LLM 超时继续使用种子，但在 UI 中明确标注“回退选题”。

## P3：排期、发布和数据反馈

实施状态：按 2026-08-13 产品决策跳过，不进入当前开发范围。现有“审核后标记发布”仅用于库存扣减和人工工作流，不扩展平台排期、自动发布或数据回流。

- 内容日历：approved 视频拖入日期和平台；
- 发布适配器接口先实现 dry-run 和导出包，再接真实平台；
- 每个平台维护标题、描述、标签、封面和比例变体；
- 状态扩展为 scheduled/publishing/published/publish_failed；
- 收集播放、完播、点赞、评论、分享等指标；
- 指标按频道、Recipe、题型、开头结构和时长聚合；
- 反馈进入选题排序，但不直接让单条爆款无限复制。

## P3：AI 制片助手

实施状态：2026-08-19 已完成 V2。助手除频道水位、任务、失败、选题和内容来源外，还会读取待审分镜、项目、Revision、Scene 和质检状态。使用 Grok 输出结构化观察与受限操作计划；会话、消息、计划、执行结果和错误全部写入 SQLite。创建/修改/暂停/恢复频道、选题决策、失败任务重试、分镜批准、单镜重生成、质量修复和版本切换必须先形成 `pending` 计划，由用户批准后才执行。目标 ID 与状态会在生成计划和执行前各校验一次，并用原子状态抢占防止重复批准。发布、删除和批量重做不在 AI 工具白名单中；人工安全删除已通过独立的影响预检和输入确认开放。

助手不是聊天装饰，而是受限工具调用层：

- “创建一个每天 3 条的天文科普频道”；
- “解释这 4 个失败任务的共同原因”；
- “把这批视频的开头改得更快，但不要改变事实内容”；
- “下周一到周五每天安排一条已通过视频”；
- “只重做第 3 镜，保持角色和画风”。

所有写操作先展示计划、影响范围和可回退性；当前版本不开放发布、批量删除和大规模重做。

## 建议优先级

| 阶段 | 结果 | 是否阻塞下一步 |
|---|---|---|
| P0 | 频道、队列、成片、审核可视化 | 是 |
| P1 | 项目版本、分镜、单镜重做、质量门禁 | 是 |
| P2 | Brand Kit、Recipe、智能选题 | 否 |
| P3 | AI 制片助手；跳过日历、发布与分析 | 否 |

不要先做复杂时间线、多人实时协作或插件市场；这些不会立刻提高当前“持续生产短视频”的产能和可靠性。
