# Pixelle-Video 下一阶段优化建议

更新时间：2026-08-26

## 1. 当前判断

项目已经具备持续生产短视频所需的主链路：多模型渠道、频道补货、动态分镜、内容门禁、并行图片生成、HyperFrames 与手绘白板渲染、字幕与逐镜导演、断点重试、版本审阅、真删除、备份与通知。当前最重要的方向不再是继续增加相似的渲染引擎，而是提高“频道配置正确率、长期运行可观测性、成片一致性和批量处理效率”。

原生图片 + HTML 与 HyperFrames 的能力和模板已经高度重叠，因此建议从用户可选制作方式中移除原生图片 + HTML。底层原生合成器仍作为原生视频的字幕/品牌叠层和 HyperFrames 故障回退存在，不对用户暴露。这样可以减少配置歧义，同时不牺牲无人值守生产的容错能力。

## 2. 推荐优先级

### P0：生产可靠性与配置正确性

1. **频道配置语义门禁**
   - 保存频道或由 AI 制片助手创建频道时，检查频道名称、选题提示词、种子池、画面风格和内容策略是否语义一致。
   - 对“生活技巧频道使用古诗种子”“科技频道使用山水国风提示词”这类明显错配给出阻断提示。
   - 保存一份生成理由和配置来源，便于追踪是人工修改、模板继承还是 AI 生成。

2. **任务级事件时间线**
   - 将规划、配音、图片、封面、渲染、质检、回退、重试记录为可展开的时间线。
   - 每一步显示开始时间、耗时、模型路由、复用/重做状态和产物路径。
   - 失败时直接给出“从哪一步恢复”，避免用户只能阅读长错误文本。

3. **恢复演练与产物清单**
   - 在设置页提供备份恢复预检和一次性恢复演练，不直接覆盖当前数据库。
   - 每个任务生成 `artifacts.json`，记录源图片、音频、封面、HyperFrames 工程、分镜视频和最终成片的哈希与引用关系。
   - 删除、重试和版本切换都以产物清单为依据，进一步降低孤儿文件和误删风险。

### P1：内容质量与品牌一致性

1. **频道视觉记忆**
   - 为每个频道维护角色、配色、构图、禁用元素和优秀样片的结构化记忆。
   - 生成画面前检索频道记忆，避免同一人物跨镜头外观漂移，或不同视频之间风格突然变化。
   - 将封面也纳入同一视觉记忆，形成稳定的频道识别度。

2. **封面工作台 V2**
   - 当前自动封面基础上，增加 2～4 个候选、标题安全区、不同平台裁切预览和点击设为当前封面。
   - 支持仅重做封面，不重新生成视频。
   - 记录封面文案、素材来源和模板版本，后续可接入 A/B 数据反馈。

3. **声音与混音工作台**
   - 增加背景音乐库、片头/片尾音效、自动闪避、响度标准化和试听。
   - 保存频道级声音预设，并允许逐镜覆盖语速、停顿和情绪。
   - 在质检中加入峰值、整体响度、静音异常和人声遮蔽检测。

4. **选题去重 V2**
   - 在现有向量语义去重上加入“核心结论、叙事角度、案例”三层相似度。
   - 允许同一主题用不同角度再次生产，但阻止标题变化、内容实质相同的重复视频。
   - 在频道页展示被跳过选题及其相似历史成片，支持人工放行。

### P1：批量操作与后台体验

1. **统一后台任务中心**
   - 将 AI 文案编排、批量重试、封面生成、场景重做、备份和源抓取统一展示为后台任务。
   - 页面可自由切换；任务完成、失败或等待人工审批时以站内通知提醒。
   - 提供取消、重试、查看日志和跳转到关联任务。

2. **批量参数审阅**
   - 队列多选后可对比制作方式、模板、声音、字幕和模型路由。
   - 批量修改前展示差异预览，只允许修改尚未冻结的字段。
   - 对已经生成素材的任务明确提示哪些修改会触发局部重做。

3. **全局搜索与筛选保存**
   - 跨频道、选题、来源、队列和成片搜索标题、文案、错误、模型和模板。
   - 支持保存常用筛选，例如“近 24 小时 HyperFrames 失败且可断点重试”。

### P2：质量评估与发布闭环

1. **自动成片抽检**
   - 抽取首帧、中点、末帧和场景边界，检测黑帧、冻结、文字溢出、画面重复和音画错位。
   - 对封面首帧单独检查标题可读性和安全区。
   - 质检失败优先局部重做，避免整条视频从头生成。

2. **平台发布适配（可选恢复）**
   - 如果后续重新进入发布阶段，先做导出包而不是直接自动发布：平台比例、标题、描述、标签、封面和字幕文件一次打包。
   - 等导出包稳定后再接入发布账号、排期和数据回流，降低账号风控和误发风险。

3. **质量与效率看板**
   - 展示每个频道的成功率、平均耗时、分步耗时、重试率、回退率和单条资源消耗。
   - 按模型渠道和模板对比，定位慢点与质量波动，而不是只看总任务状态。

## 3. 暂不建议增加的内容

- 暂不再增加与 HyperFrames 重叠的 HTML 渲染引擎；优先扩充和版本化 HyperFrames 模板。
- 暂不恢复数字人、动作迁移和 ComfyUI 链路，它们会重新扩大运维面且不符合当前低画面成本、持续批量生产目标。
- 暂不以更多模型数量作为升级目标；模型渠道应围绕健康检查、自动切换和任务可复现性完善。
- 不把连续 20 次 Ubuntu 渲染作为日常验证。仅在 HyperFrames、Chromium、FFmpeg 或容器运行时升级时执行专项压力门禁。

## 4. 建议实施顺序

1. 频道配置语义门禁 + 任务事件时间线。
2. 频道视觉记忆 + 封面工作台 V2。
3. 统一后台任务中心 + 批量参数审阅。
4. 声音混音工作台 + 自动成片抽检。
5. 根据实际运营需求决定是否恢复平台发布和数据反馈阶段。

这一路线的核心目标是：让系统不仅“能生成”，还能够在无人值守运行时持续生成正确频道、正确风格、可追踪、可恢复的成片。
