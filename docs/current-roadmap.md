## 3. Wave 1：真实渠道与服务器 Beta

目标：在目标 Docker 服务器完成小范围真实用户验证。

- 服务器执行 `docker compose --env-file .env -f infra/docker-compose.yml up -d --build`、健康检查、重启恢复和资产持久化验证。
- 核对外部 PostgreSQL/Redis 网络、迁移、备份、连接池、`APP_SECRET`、HTTPS、注册开关和日志脱敏。
- ✅ 已使用当前 `.env` 配置的 OpenAI-compatible 文本渠道 + Grok 图片网关跑通固定样本：6 页结构化 Storyboard、1 张原生中文封面、图片转存成功；报告位于 `fixtures/reports/live.json`。
- ⏳ 官方 OpenAI 与 xAI 直连渠道仍需在配置对应密钥后分别验证，并记录成功率、耗时、并发、成本、错字和图片下载失败。
- 抽样验证模型原生中文出图、预期文案记录和失败重试；不再将字体或确定性渲染作为部署前置条件。
- 支付宝/微信先接沙箱或小额真实订单，验证预下单、回调验签、查单、幂等入账和订单过期。
- 完成 20 套不同主题的人工评审，建立“可发布/需返修/不可用”判定和截图归档。

Beta 退出条件：P0 清零；四项根命令全绿；真实渠道和支付各有成功与失败样本；服务器重启不丢资产、不重复扣费；注册与管理员权限符合预期。

## 4. Wave 2：质量与运营基础

目标：降低人工返修率和线上排障成本。

- 局部重绘框选 UI，展示 mask/整页降级原因和新旧版本关系。
- 完善原生图片文字质量检查：视觉模型可用时做 OCR/视觉审查，不可用时明确进入人工复核，不静默宣称通过。
- 增加页面溢出、图片尺寸、字体缺失、空响应、下载超时、Provider 429/5xx 的统一质量门。
- 补齐 compatible/xAI 合同测试、真实调用报告脱敏、结构化日志、请求关联 ID 和成本告警。
- 增加管理员操作审计、角色权限细分、会话撤销/设备管理和注册风控。
- 把 Docker 内存、CPU、队列等待和 Provider 限流做成可重复的服务器验收报告。

## 5. Wave 3：按需求扩展基础设施

只有当出现多实例、并发持续超过单进程能力、队列优先级或多人协作需求时启动：

- Redis/BullMQ 队列、独立 `apps/worker`、分布式租约和优先级调度。
- 对象存储（S3/R2 等）替换本地资产存储，保留资产血缘和版本语义。
- PostgreSQL 读写分离、连接池和更完整的迁移/回滚演练。

Redis 已在服务器环境中预留，但“已存在服务”不等于“当前应用已使用”。在没有实际瓶颈前保持单容器、进程内 Runner，有利于节省资源和降低运维复杂度。

## 6. Wave 4：平台发布与商业化

在 Beta 证明内容质量和用户需求后，再按平台授权条件实施：

- 小红书、抖音、微信公众号的草稿/发布 Adapter、授权 token 管理、定时队列和失败重试。
- 内容日历、发布状态、平台差异化文案和素材规格校验。
- CSV/平台数据导入、表现复盘、A/B 实验、模板与 Recipe 市场。
- 按用户、模型、分辨率、图片编辑和发布能力拆分可配置计费。

React Flow 画布、MCP Server 和开放 API 暂不作为近期前置条件；它们要在出现明确的自动化编排或第三方集成需求后单独立项。

## 7. 每个版本的统一发布门禁

```text
代码门禁：lint / typecheck / test / build 全绿
数据门禁：迁移可重复，备份可恢复，用户与计费数据不丢
安全门禁：真实支付 fail-closed，密钥不进日志，资源归属有测试
生成门禁：Mock 固定集达标，真实渠道有小样本报告
部署门禁：健康检查、重启恢复、资产持久化、并发/内存报告
产品门禁：人工评审通过，导出包可直接进入目标平台编辑/发布
```
