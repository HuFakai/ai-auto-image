## 二、已落地能力

### 1. 工程与运行时

- TypeScript Monorepo：`apps/web` + 10 个 packages，pnpm + Turborepo，strict TypeScript。
- Next.js Studio、API Route 和进程内 Job Runner 已接通。
- 数据层已经切换为 PostgreSQL 方言：生产通过 `DATABASE_URL` 连接 PostgreSQL；本地/测试无连接串时使用进程内 PGlite，见 `packages/storage/src/database.ts`。
- 当前核心 Schema 共 31 张表，覆盖项目、运行、节点、资产、作业、渠道、品牌、用户、会话、套餐、订单、钱包、订阅、点数流水、支付配置和卡密系统；旧 SQLite → PostgreSQL 导入工具仍只覆盖迁移前的 22 张业务表。
- Dockerfile 已使用多阶段构建、standalone 产物、非 root 用户、健康检查和 `/data` 资产卷；生产 Compose 连接外部 PostgreSQL，Redis 仅作为可选预留。
- 生产 Compose 已将根目录 `.env` 同时作为插值来源和容器运行时环境来源，固定绑定 `127.0.0.1:1235`，要求显式 `APP_SECRET`，默认内存上限 4G；模型调用不设全局并发，只有后台渠道正整数上限会生效，`0` 表示不限制。

### 2. AI 生成和工作流

- 9 种内容类型：知识卡片、科普漫画、金句卡、清单卡、对比卡、产品种草、图书推荐、长文拆解、四格漫画。
- 当前运行时按两条管线组织：`comic_story` / `strip_comic` 走漫画管线，其余类型复用知识卡片管线骨架；这意味着“支持类型”已经落地，但不是每种类型都有完全独立的编排器。
- Provider 层支持自建领域接口、OpenAI-compatible Wire、OpenAI 官方和 xAI/Grok 适配，以及 Mock Provider；文本和图片渠道可以独立配置、排序、启停、测试和回退。
- 图片主流程统一使用图片模型原生生成包含中文的最终图片；确定性文字排版与 `auto_fallback` 已从新建、重试和单页重生流程删除。文本、图片、图生图和视觉检查统一服从被调用模型渠道的共享并发配置，默认 `0` 不限制。
- 任务具备租约、心跳、看门狗、幂等键、重启恢复、取消和单页局部重试语义。

### 3. 编辑、视觉和交付

- 六套内置品牌/风格预设、Logo、水印、签名、色板和封面模板配置已接入 Brand Kit。
- 单页返修、版本链、重新排版、重新生成、局部重绘 API、封面候选、封面选择、平台比例适配和 ZIP 导出已具备。
- 评审状态、发布文案生成/复制、URL 资料导入、图片上传、SSRF 防护和生成用量展示已接入工作台。
- 当前 UI 已采用方案 A「暗室暗房」的 v2 方向；其他静态方案仅作为设计档案保留。

### 4. 账号、计费和支付

- 账号密码登录、注册、服务端会话、用户资源隔离、管理员路由和注册开关已实现。
- 套餐、点数包、钱包、订阅、点数流水、订单、支付宝/微信支付配置与通知接口已实现第一版。
- 当前计费约定是 1 张图片消耗 1 点，新用户可获得初始点数；具体生产价格和权益仍需要产品确认并配套验收。

### 5. 卡密系统（当前增量）

- 迁移 `0010_card_code_system.sql` 已加入系统开关、批次、单卡、兑换记录、外部 API Key、幂等记录、Webhook 投递和审计表；卡密明文只在生成响应中出现，数据库只保存 HMAC 摘要和脱敏字段。
- `/admin/cards` 已支持总开关、用户兑换/API 子开关、点数卡/会员卡/组合卡批量生成、一次性 CSV、批次/单卡停用、API Key scope/IP 白名单/限流/过期时间和投递记录。
- 充值中心已支持用户兑换；兑换事务同时写入钱包、订单、点数明细、订阅和审计记录，并排除在站内支付收入统计之外。
- `/api/v1/cards/*` 已支持外部生成、幂等重放、批次/单卡查询、单卡停用和签名 Webhook 自动退避重试；当前限流为单应用进程内实现，多实例前再迁移 Redis。
- 卡密总开关默认关闭，完成小批量内部兑换和对账后，才应在管理后台开启用户兑换；外部 API 需单独创建 Key 并最后开启。

## 四、本轮 P0 修复结果

### P0：支付 fail-closed（已修复）

`apps/web/src/server/pay/service.ts` 增加生产环境硬门禁：生产环境既不能创建 `mock` 订单，也不能调用 `dev-confirm`；支付宝/微信未配置或未启用时返回 503，不再静默降级为 mock。`PAYMENT_MOCK_ENABLED` 仅作为非生产环境开关，生产环境即使误设为 1 也无效。安全回归测试位于 `apps/web/src/server/pay/service.test.ts`。

### P0：点数预留、结算与释放（已修复）

`wallets.reserved_credits` 和 `workflow_runs.credits_reserved/credits_charged` 已加入迁移。知识卡片、漫画、封面候选、单页返修和局部重绘均在图片 Provider 调用前原子预留；成功图片从预留中结算，失败/取消释放剩余额度，重试按已结算数量补足。当前新建、重试和单页重生均直接调用图片 Provider，不再存在确定性排版的免费分支。

钱包扣减已改为只允许全额扣减，不再“余额不足扣到 0”静默少扣。相同节点的重复完成不会重复触发结算钩子；若结算钩子失败，节点置为 failed，重试优先复用已落盘产物，不重复调用 Provider。相关并发/幂等测试位于 `packages/storage/src/billing-hooks.test.ts` 和 `apps/web/src/server/billing.test.ts`。

### P0：工程质量门禁（已修复）

已清理存储层 lint 错误，并为 PGlite 计费/存储、Web 和工作流集成测试配置合理默认超时；支付、并发预留/结算、重复节点回调已经进入默认测试集。

## 五、P1 修复结果与仍待事项

1. **SQLite → PostgreSQL 迁移工具已补齐**：`scripts/pg-export.mts` / `scripts/pg-import.mts` 共用当前 22 张表白名单，覆盖用户、会话、套餐、订单、钱包、订阅、点数流水和支付配置；导出 manifest 记录格式版本与源库缺表，导入校验文件校验和，`--truncate` 才会显式清空目标表并校验目标行数。生产正式备份仍使用 PostgreSQL 原生备份；本轮未对线上 PG 执行破坏性的 `--truncate` 导入。

2. **生产联调部分完成**：当前配置的兼容文本/图片网关已跑通固定真实样本，并修复 DeepSeek reasoning-only 返回与网关 `thinking` 参数差异；目标服务器 Docker、反向代理、中文字体、外部 PostgreSQL/Redis 连通性、官方 OpenAI/xAI 直连和支付宝/微信回调仍需要实测记录。
3. **权限模型仍是第一版**：已有 admin/user 基础角色和资源归属，但还没有完整 RBAC、管理员操作审计和更严格的跨用户测试；公网开放前需要补齐。
4. **质量检查仍偏规则与人工**：原生图片中文字视觉审查依赖支持视觉输入的文本渠道；局部重绘 API 已有，框选 UI 尚未闭环。
5. **部署性能数据未形成报告**：Compose 已设置 4G 内存限制，模型渠道默认不限制并发，但当前没有目标服务器的峰值、队列等待和外部 Provider 限流数据。`infra/verify-deployment.sh` 的内存检查仍主要依赖人工观察，真实生成烟测默认关闭以避免意外消费额度。
6. **Provider 测试覆盖不均衡**：OpenAI-compatible 的流式解析、multipart 文本、DeepSeek reasoning 开关已有合同测试；官方 OpenAI/xAI 直连端点行为仍需合同测试和带脱敏报告的真实验证。
