# ADR-0003：图片文字统一采用模型原生生成

状态：已取代（2026-09-01）

## 背景

早期版本同时提供模型原生图片和 Satori/SVG + Sharp 确定性文字排版。实际使用表明，当前主力图片模型已经能够较好地生成中文，继续维护两条生产链路会增加模板、字体、镜像和计费分支的复杂度，也会让重试与历史兼容更难判断。

## 决策

1. 新建、从头重试、检查点恢复、单页重生和漫画页面统一由图片模型直接生成包含中文的最终图片。
2. 删除 `native` / `deterministic` / `auto_fallback` 的用户可见开关、确定性正文排版 API、生产渲染器、字体下载与镜像复制步骤。
3. 服务端继续保存预期文案、模型响应元数据和质量检查结果；文字质量异常通过质量检查、失败状态和重试处理，不静默转入本地排版。
4. 历史作品不批量改写、不删除既有资产；详情页、下载和旧元数据读取保留兼容，确保升级不会破坏已完成作品。
5. 品牌 Logo、水印或签名叠加属于品牌资产处理，不属于正文排版，仍可使用轻量的 Sharp 图像处理。

## 后果

- 图片模型承担文字与画面的最终融合，服务器不再下载中文字体或运行确定性正文合成，因此镜像更小、本地 CPU/内存开销更低。
- 修改标题、价格或正文需要重新调用图片模型；产品界面必须明确提示可能产生的点数消耗，并提供失败页面级/单图级重试。
- 价格、参数和中文准确性依赖预期文案、模型能力与质量检查，后续应优先完善质量审查和重试体验，而不是重新引入第二条正文排版链路。
- Playwright/Chromium 不属于生成运行时；如未来出现新的可编辑排版需求，应单独评估隔离服务，不得悄悄恢复到当前生产流程。
