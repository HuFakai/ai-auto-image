## 二、升级批次(按优先级)

### 批次 1(P0):多平台一键适配 —— 借鉴 Taplio/WaveGen
**一句话**:一次创作,导出小红书/抖音/公众号/Instagram 四种规格。
- deterministic 模式**零模型费用重排**:同一 run 换 aspectRatio(3:4 / 9:16 / 横版 4:3 / 1:1)重新排版出全套图——渲染引擎已参数化,只差"按目标平台批量重排 + 打包"。
- native 模式:平台风格提示词变体(竖版大字 vs 横版杂志)。
- 发布文案按平台变体(小红书标签风 / 公众号摘要风)。
- 落点:`export` 路由加 `platforms[]` 参数;新增"平台包"导出目录结构;UI 导出对话框多选。
- 工作量:2 天。**收益/成本最高的一项**。

### 批次 2(P0):页内编辑闭环 —— 借鉴 Gamma/Canva
**一句话**:生成后不用重跑整个 run,逐页改字/改图即所得。
- 文字编辑:deterministic 页面在详情页直接改 headline/body → 已有 rerender(零费用重排)API,补一个页内编辑交互(点击文字→改→重排本页)。
- 图面编辑:repaint API 已就绪,补**框选区域 UI**(画布上拖框→输入改动描述→区域重绘,整页降级已有)。
- 批量应用:改 Brand Kit 后"一键重排全部 deterministic 页"。
- 工作量:2–3 天。补齐"生成→微调→定稿"体验断层。

### 批次 3(P1):封面引擎 —— 借鉴 RedInk
**一句话**:封面单独一道工序,出 3 个候选,人工挑。
- 封面专属生成:独立节点出 3 个候选(不同标题 Hook/构图/配色),复用现有逐页并发;审批门扩展为"封面候选选择"。
- Hook 文案库:按内容类型内置标题公式(数字型/悬念型/对比型/直给型),prompt 注入。
- 封面规则评分:标题字数、与首图差异化、Brand Kit 一致性;可选视觉模型打分(渠道就绪后)。
- 工作量:2–3 天。小红书点击率的核心杠杆。

### 批次 4(P1):版式引擎升级 —— 借鉴 Gamma Smart Layouts
**一句话**:版式跟着内容走,新增六种高表现力版式。
- 新版式(确定性渲染):数据大字卡(大数字+注释)、时间线、真表格对比、目录页、金句引言页、步骤流程页。
- storyboard 的 `layoutHint` 从"提示"升级为"版式路由":LLM 按 content type 输出 hint → 渲染引擎路由到对应版式组件。
- 每种版式配 eval 用例。
- 工作量:3–4 天。卡片质量与信息密度直接提升。

### 批次 5(P2):内容日历与数据回流 —— 借鉴 Postiz + 路线图 5.2/5.3
**一句话**:从生成工具升级为运营工作台,形成"选题→生成→发布→复盘"闭环。
- 内容日历:月/周视图,run 关联"计划发布日/平台/状态(待发/已发)";手动登记发布(不做自动发布,规避平台风控;小红书集成走可选外挂,见批次 6)。
- 数据回流:CSV 导入表现数据(曝光/点击/赞藏评),关联到 run/版本;复盘页(哪类主题/版式/标题表现最好)。
- 封面/标题 A/B:封面引擎的 3 候选天然成为 A/B 素材,回流数据定胜负。
- 工作量:3–4 天(日历 1.5 + 回流 2)。

### 批次 6(P2):发布集成与模板包 —— 借鉴 Postiz + 路线图 5.4
- 小红书:集成开源 [xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) 作为**可选外挂**(扫码登录在用户本地,核心服务不存 cookie——遵守阶段 3 文档的安全边界),本项目提供"生成→推送草稿"按钮。
- 公众号:官方草稿 API(图床上传 + 创建草稿,不自动发布)。
- Recipe/主题/Brand Kit 打包导出 JSON → 导入安装(社区分享基础)。
- 工作量:3–4 天。

### 远期(按需)
- **选题助手**:热榜手动粘贴 + AI 拓展 10 个角度 + 选题库;订阅源自动产出(WaveGen 式)。
- **图文转视频**:图文包→幻灯片视频(图片轮播+BGM+字幕),参考仓库内 Auto-AI-Video 项目;进入短视频场景。
- **多模态质检**:视觉模型对 native 页面做错字检查(接口已预留,等支持视觉的渠道)。

## 三、执行建议

1. 顺序:1 → 2 → 3 → 4 → 5 → 6;批次 1/2 是日用体验,3/4 是质量跃升,5/6 是运营闭环。
2. 每批沿用现有节奏:开发 → 全仓四门验证 → 中文提交推送;涉及 schema 的(批次 5)先出迁移再动代码。
3. 不做清单(延续既定边界):自动发布/群发、绕过平台风控、爬虫式热点抓取(只做手动粘贴)。
