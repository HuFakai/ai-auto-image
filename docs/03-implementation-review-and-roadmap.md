## 1. 评审结论总览

五条技术主链路（Provider、渲染、SQLite 作业、持久化存储、Web 产品）已全部跑通真实 API 端到端验证，但**各阶段均存在未完成的交付物**，其中阶段 0/1 的"验证类退出条件"（Docker 服务器实测、内存基准、评测集指标、20 套人工评审）和阶段 2/3 的核心深度能力（角色参考图、气泡渲染、审批暂停、PG/Redis 迁移）缺口最大。

| 阶段 | 完成度 | 出口判断 |
|---|---|---|

| 阶段 1 | ~85% | ❌ 仅差 20 套人工评审（工具已备：批量创建 + 评审标记/筛选）；URL 抓取、图片上传、编辑器、导出、Brand Kit 均已实测 |
| 阶段 2 | ~45% | ❌ 差角色参考图、气泡渲染、局部重绘、漫画端到端实测 |

| 阶段 4 | ~30% | ❌ 差认证/RBAC、数据回流、A/B、市场、计费 |

## 2. 已验证通过的能力（有真实证据）

- 双 Provider 真实调用：Grok `grok-imagine-image-2.0` 出图（约 20s/页），deepseek-v4-flash 结构化输出全部通过 Zod 校验。
- **native 模式**：8 页知识卡片端到端（Brief → Storyboard → 8 图 → 质量检查 → ZIP），图内中文零错字。
- **deterministic 模式**：8 页图书推荐端到端，Satori 中文合成 + 视觉层插画合成正常，主题切换即重渲染。
- 局部返修：单页重生成 26s 完成，仅目标页重跑，旧版本保留（Revision 软删除）。
- 崩溃恢复：进程被杀后重启，孤儿 job 自动回收续跑（已修复 stale 阈值 bug）。
- 导出：两种模式各产出 9 文件 ZIP（按序图片 + 发布文案 Markdown + 发布清单）。
- 9 个单元测试全绿；typecheck / 生产构建（standalone）全绿。
- 密钥安全：真实 Key 未进入 git（仅占位符 `.env.example` 被跟踪）。

## 4. 已知技术债与风险

1. **无认证即公网部署的风险**：当前单用户假设（`ws_default` 硬编码）。部署 checklist 必须二选一：仅内网/VPN 部署，或提前实现最小 token 登录。
2. **取消语义不完整**：运行中的图片调用无法被取消（AbortSignal 未接到 cancel API）。
3. **渠道能力限制**：grok.aisenno.com 当前仅文生图。`edit()`/Mask/参考图编辑代码就绪但不可实测，阶段 2 的局部重绘与角色参考图编辑链路被渠道阻塞。
4. **无多模态审查**：原生文字准确性检查目前是"人工核对清单"而非自动 OCR 比对；`auto_fallback` 的自动询问流未实现。
5. **结构化日志缺失**：console.log 为主，未接 pino 结构化 JSON 日志与轮转。
6. **失败调用的成本盲区**：失败/重试的 token 与图片调用未记入 usage（成功的才记）。
7. **Next 多 bundle 单例问题**：已用 `globalThis` 守卫修复 runner 重复启动；迭代 2 另修复「慢调用期间租约 60s 过期被其他 runner 实例误回收」——心跳续租已改为 Runner 职责（handler 运行期自动续租）。
8. **`auto_fallback` 模式**：枚举与 API 已接受该值，但执行器未实现"失败后询问再切"的流程。

## 5. 下一步开发计划（5 个迭代）

> 原则：先补"验证与安全"（阶段 0/1 真正出口），再补漫画深度能力，再做基建迁移，最后平台化。
> 每个迭代结束跑一次全量 typecheck + test + build，并更新本文件的状态表。
