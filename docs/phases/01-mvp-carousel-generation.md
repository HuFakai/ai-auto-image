# 阶段 1：图文生成 MVP

> 文档定位：原始阶段范围与验收基线。实现已发生演进，本文不作为当前待办清单；当前执行以 [当前状态](../current-status.md) 和 [当前路线图](../current-roadmap.md) 为准。

## 1. 阶段目标

交付一个可实际使用的 Web 产品：用户输入主题、文章或商品资料，选择内容类型和平台后，自动生成一套 6–10 页图文；用户可以修改文案、替换素材、单页重生成，并导出可发布图片包。

## 2. 首版用户场景

### 知识卡片

输入一个主题或文章，输出封面、知识点、案例、总结和 CTA。

### 文章拆解

输入长文或 Markdown，输出摘要、观点、证据和结论卡片。

### 图书推荐

输入书名、简介和摘录，输出推荐理由、核心观点、适合人群和行动建议。

### 产品宣传/图文带货

输入商品图、卖点、参数、价格和目标人群，输出封面、痛点、卖点、使用场景、参数和 CTA。

## 3. MVP 范围

### 输入

- 主题文本。
- 粘贴文章或 Markdown。
- 商品资料表单。
- 上传图片。
- URL 抓取作为实验能力，失败时允许用户粘贴正文。

### 输出

- 小红书 3:4。
- 抖音图文 9:16。
- 微信公众号正文插图 16:9 或自定义横图。
- PNG/JPEG 单图和 ZIP。
- 平台标题、正文、标签和发布备注 Markdown。

### 不包含

- 自动正式发布。
- 漫画和复杂角色一致性。
- 可视化 DAG 编辑器。
- 团队多租户和付费。

## 4. 核心页面

### 项目列表

- 新建项目。
- 按状态筛选。
- 显示 Recipe、平台、更新时间和封面。
- 复制、归档和删除。

### 创建向导

1. 选择输入方式。
2. 选择 Recipe。
3. 选择平台和比例。
4. 选择 Brand Kit 或临时风格。
5. 选择文字模式；默认“模型原生文字”，可开启“确定性文字渲染”。
6. 使用后台模型渠道的并发配置；创作页不再提供用户级并发设置。
7. 预览 Content Brief。
8. 确认后开始生成。

### 生成进度页

- 节点级进度。
- 已完成页面即时预览。
- 预计费用区间和实际费用。
- 取消、暂停和重试。

### 图文编辑器

- 左侧页面缩略图和拖动排序。
- 中央画布预览。
- 右侧文字、主题、图片和页面设置。
- 单页重新生成背景、重新排版和恢复版本。

### 导出页

- 平台预检。
- 图片顺序。
- 标题、正文、标签复制。
- ZIP 下载。
- 发布清单和风险提醒。

## 5. Recipe 设计

每个 Recipe 包含：

```text
recipe.yaml
schemas/input.ts
schemas/output.ts
prompts/brief.md
prompts/storyboard.md
prompts/visual.md
templates/
quality-rules.ts
examples/
```

Recipe 不能直接调用 SDK，只能声明所需能力并通过 `ai-core` 调用。

### Recipe 输出约束

- 封面只有一个主标题和一个辅助信息区。
- 单页只表达一个核心观点。
- 正文卡片不超过定义的文字密度。
- 最后一页包含总结或 CTA。
- 商品价格和参数必须来自用户输入，不允许模型编造。
- 图书摘录必须标记来源或用户提供状态。

## 6. Brand Kit

支持：

- 品牌名称和 Logo。
- 主色、辅助色和背景色。
- 标题与正文字体。
- 圆角、阴影、边框和留白风格。
- 水印和账号署名。
- 文案语气和禁用表达。
- 图片风格关键词和负面关键词。

提供至少 6 套内置主题：

- 极简知识。
- 杂志编辑。
- 高对比营销。
- 莫兰迪生活。
- 科技深色。
- 图书纸张。

## 7. 文案和 Storyboard 流程

```text
Input
  → Content Brief
  → 6–8 个标题候选
  → 选择最优标题或用户确认
  → Storyboard
  → Slide Copy
  → Visual Prompt Plan
```

MVP 可以提供“自动模式”和“确认模式”：

- 自动模式：系统选择标题并继续。
- 确认模式：用户确认 Brief 和标题后再生成图片。

## 8. 图片生产策略

系统支持两种图片生产方式。

### 原生文字模式（默认）

- 使用 `grok-imagine-image-2.0` 或 `gpt-image-2` 直接生成完整页面，包括中文标题和正文。
- Prompt 注入已确认的逐页精确文案、画布比例、视觉层级和禁止额外文字等要求。
- 模型输出作为最终视觉稿，服务器不再执行文字叠加。
- 质量审查保存预期文案和检查结果；发现文字问题时允许单页重试或切换确定性模式。
- 修改页面文字需要重新调用图片模型，界面必须提前提示可能产生费用。

### 确定性文字模式（可选，默认关闭）

页面拆为三层：

1. **背景层**：纯色、渐变、纹理和装饰。
2. **视觉层**：AI 插画、商品图、人物、图形或照片。
3. **信息层**：标题、正文、价格、标签、Logo 和页码。

AI 生成视觉层，信息层由 Render Engine 输出。

商品类图片流程：

- 原始商品图校验。
- 可选自动抠图。
- AI 生成场景背景。
- 商品图与背景确定性合成。
- 开启确定性模式时，卖点、价格和 CTA 由程序渲染；原生模式则由模型按已确认文案生成，并进行准确性审查。

## 9. 页面编辑和版本

每次操作生成轻量 Revision：

- 确定性模式下，文案或主题修改只触发重新渲染。
- 原生模式下，文案修改通常需要重新调用图片模型；纯裁剪、顺序和导出参数修改不需要。
- 图片 Prompt 修改只重新生成当前视觉资产。
- 页面重新生成保留原版本。
- 页面顺序调整不触发 AI 调用。

必须显示“此操作是否产生模型费用”。

## 10. 质量检查

### 确定性检查

- 文字是否溢出。
- 字号是否低于移动端阈值。
- 对比度是否达标。
- Logo 是否超出安全区。
- 画布比例和尺寸是否正确。
- 图片是否缺失或分辨率不足。
- 商品价格是否与输入一致。

### 原生文字检查

- 将预期文案与多模态/OCR 识别结果进行比较。
- 检查是否缺字、错字、重复字或出现未要求文字。
- 价格、参数、书名等高风险字段要求更严格的匹配。
- 失败后提供“原生模式重试”和“切换确定性渲染”两种操作，不静默增加费用。

### LLM 检查

- 是否偏离主题。
- 每页是否只表达一个核心观点。
- 是否存在重复、空话和不受支持的断言。
- 平台标题、正文和图片是否一致。

### 可选视觉模型检查

- 主体是否被文字遮挡。
- 图片与页面主题是否一致。
- 是否包含意外文字、Logo 或水印。

## 11. API 草案

```text
POST   /api/projects
GET    /api/projects/:id
POST   /api/projects/:id/brief
POST   /api/projects/:id/generate
GET    /api/runs/:id
POST   /api/runs/:id/cancel
POST   /api/slides/:id/regenerate-asset
PATCH  /api/slides/:id
POST   /api/projects/:id/render
POST   /api/projects/:id/export
GET    /api/exports/:id/download
```

`POST /api/projects/:id/generate` 接受：

```ts
{
  textRenderingMode?: "native" | "deterministic" | "auto_fallback"; // 默认 native
}
```

运行详情冻结并展示当次使用渠道的并发上限；`0` 显示为“不限制”。

## 12. 测试计划

### 固定评测集

至少覆盖：

- 中文知识主题。
- 3000 字长文。
- 一本书及真实摘录。
- 有完整参数的商品。
- 缺少部分参数的商品。
- 包含敏感或夸大表达的输入。

### 自动测试

- 四种 Recipe Schema。
- 自动分页和文字密度。
- 主题切换视觉快照。
- 单页重生成。
- ZIP 内容和顺序。
- Provider 切换。
- 原生/确定性文字模式切换。
- 文本/图片渠道并发门（0 不限制、正整数限流）和 429 指数退避。
- Docker 应用重启后通过 SQLite `jobs` 表恢复任务。
- SQLite WAL、备份恢复和磁盘空间不足场景。
- 生产镜像不包含 Chromium、Playwright、Redis、PostgreSQL 或 MinIO 服务。

### 人工验收

- 分别使用 OpenAI 和 Grok 完成至少一套 8 页作品。
- 检查手机实际阅读效果。
- 在确定性文字模式下修改任意一页标题并在不调用 AI 的情况下重新导出；原生模式下明确提示需要重新生成图片。

## 13. 交付物

- 可使用的 Web MVP。
- 四种 Recipe。
- 六套主题。
- OpenAI、Grok 和自定义兼容 Provider 设置页。
- 页面编辑与 Revision。
- PNG/JPEG/ZIP 导出。
- 发布文案包。
- MVP 使用文档和部署文档。

## 14. 验收标准

- 从输入到 6–10 页预览能够端到端完成。
- 结构化输出解析成功率不低于 99%。
- 页面渲染成功率不低于 99.5%。
- 默认由主力图片模型生成中文；确定性文字渲染开关默认关闭且可以按项目、Run 或单页开启。
- 原生文字检查失败时能够单页重试或切换到确定性渲染兜底。
- 文本和图片模型仅服从后台渠道并发配置，默认 `0` 不限制。
- 单页修改不会触发整套重新生成。
- 同一项目可以在 OpenAI 和 Grok 之间切换。
- 导出包包含图片、平台文案、生成信息和发布清单。
- 用户未授权时不存在任何外部平台写入。

## 15. 退出条件

至少有 20 个不同主题的完整作品通过人工评审，四种 Recipe 均完成真实使用验证，且核心失败可以通过局部重试恢复后，进入阶段 2。
