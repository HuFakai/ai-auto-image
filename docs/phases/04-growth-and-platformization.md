# 阶段 4：运营闭环与平台化

> 文档定位：长期产品化能力基线，不是当前迭代待办。当前执行以 [当前状态](../current-status.md) 和 [当前路线图](../current-roadmap.md) 为准。

## 1. 阶段目标

将单人内容工具升级为支持多账号、多品牌、团队协作、数据复盘、模板生态和成本治理的平台，并让优质内容表现持续反哺后续创作。

## 2. 范围

- Workspace、成员和角色权限。
- 多品牌、多账号和内容资产库。
- 模板与 Recipe 市场。
- 自定义 Skill 和 Workflow 发布。
- 数据采集、内容表现和复盘。
- A/B 标题、封面和发布时间实验。
- 风格偏好学习。
- 成本、额度、限流和 Provider 路由。
- API Key、Webhook 和第三方集成。
- 商业化和计费基础。

## 3. 多租户与权限

### 角色

- Owner：账单、安全和所有资源。
- Admin：成员、品牌、Provider 和平台账号。
- Editor：创建、编辑和运行工作流。
- Reviewer：审核和批准终稿。
- Publisher：授权草稿和发布。
- Viewer：只读。

生成审批和发布审批可以要求不同角色完成。

### 隔离

- 数据库记录带 Workspace ID。
- 对象存储使用 Workspace 前缀和签名 URL。
- Provider Key 与平台凭证按 Workspace 加密。
- 独立 Worker 从 Redis/BullMQ 获取任务后校验租户边界。

## 4. 内容资产库

支持：

- 按项目、品牌、角色、场景、商品和平台检索。
- 资产标签和全文检索。
- 参考图许可范围。
- 相似素材查找。
- 重复素材检测。
- 资产过期和删除策略。
- 衍生版本和使用历史。

内容资产库不只是文件列表，还要显示每个资产由哪个输入、Prompt、模型和父资产生成。

## 5. 模板、Recipe 与 Skill 市场

### 发布单位

- Theme：视觉主题。
- Template：页面模板。
- Recipe：端到端内容类型。
- Skill：可复用单步能力。
- Workflow：完整流程。

### 发布要求

- 名称、版本、作者和许可证。
- 输入输出 Schema。
- 所需模型和平台能力。
- 示例和预览。
- 权限与外部访问声明。
- 测试结果和兼容版本。
- 安全扫描。

第三方 Skill 默认不能执行任意本地命令，也不能访问未声明的凭证和网络目标。

## 6. 数据回流

数据模型至少包含：

- 平台、账号、内容和发布时间。
- 展示、阅读、点赞、收藏、评论、转发和关注转化。
- 商品点击、加购和成交数据，在用户可合法提供时接入。
- 标题、封面、Recipe、主题、模型和 Prompt 版本。
- 数据采集时间和来源。

平台数据不可得时，支持 CSV 导入和手动录入。

## 7. 内容复盘

复盘输出：

- 本次表现与账号基线对比。
- 同平台、同内容类型和相近发布时间对比。
- 可能有效的标题、封面和结构因素。
- 无法确定的归因。
- 下一次唯一或少量可验证实验。

避免把相关性描述为因果关系。样本不足时不更新稳定偏好。

## 8. A/B 实验

支持：

- 标题候选。
- 封面构图和颜色。
- 首屏 Hook。
- CTA。
- 发布时间。

实验记录必须锁定除实验变量之外的其他关键因素，并声明主要指标、观察窗口和停止条件。

## 9. 风格偏好学习

风格学习来源：

- 用户明确保存为偏好。
- 多次重复的人工修改。
- 经数据验证的稳定表现。

偏好分层：

- 用户偏好。
- Brand Kit 偏好。
- Recipe 偏好。
- 平台偏好。

单次修改只作为观察，不自动覆盖 Brand Kit。

## 10. 成本治理

### 预算

- Workspace 月预算。
- 项目预算。
- Workflow Run 预算。
- 单节点最大费用。

### 路由

- 草稿使用低成本模型。
- 封面和最终图使用高质量模型。
- Provider 限流时选择允许的备用 Provider。
- 只有能力兼容时才自动降级。

### 成本展示

- 执行前估算区间。
- 执行中累计。
- 执行后按节点、模型和资产拆分。
- 缓存节省和重试成本单独显示。

## 11. 商业化基础

可选计费维度：

- 席位。
- 工作区数量。
- 存储量。
- 工作流运行次数。
- AI 成本加服务费。
- 高级模板和 Recipe。
- 发布账号数量。

账单系统不能依赖模型估算费用，必须使用实际 Provider usage 或可验证的本地计价规则。

## 12. 开放平台

### API

- Workspace API Key。
- 细粒度 Scope。
- 限流和审计。
- 异步任务和 Webhook。
- OpenAPI 文档和 SDK。

### MCP

- 创建项目。
- 运行 Recipe/Workflow。
- 查询和返修。
- 导出。
- 在单独授权下创建平台草稿。

### Webhook

- Run 完成或失败。
- 等待审批。
- 草稿创建。
- 发布完成或失败。
- 预算阈值。

## 13. 可观测性与运维

- 按租户、Provider、Recipe 和版本查看成功率。
- 节点耗时和队列等待时间。
- 生成质量反馈。
- Provider 限流和错误趋势。
- 平台 Adapter 健康状态。
- 资产存储和 CDN 成本。
- Prompt 回归告警。

关键 Provider 和平台 Adapter 应提供熔断、降级和停用开关。

## 14. 测试计划

- 多租户数据隔离测试。
- 角色权限和审批分离测试。
- 第三方模板/Skill 安全测试。
- 账单和成本核对。
- 数据导入、去重和回填。
- A/B 实验分组和指标计算。
- 大量并行任务压力测试。
- Provider 故障、Redis/BullMQ 和 Worker 恢复演练。

## 15. 交付物

- Workspace 与 RBAC。
- 多 Brand Kit 和平台账号。
- 内容资产库。
- 模板、Recipe、Skill 和 Workflow 市场。
- 数据导入和运营看板。
- 内容复盘和实验系统。
- 成本预算和智能路由。
- 开放 API、MCP 和 Webhook。
- 计费基础设施。

## 16. 验收标准

- 不同 Workspace 无法访问彼此数据和资产。
- 审核者和发布者权限可以分离。
- 用户能发布一个经过安全校验的自定义 Recipe。
- 内容表现数据能关联到具体版本、主题、模型和 Prompt。
- 预算超限可以在产生额外费用前阻止任务。
- Provider 故障时，兼容任务能够安全降级，不兼容任务明确失败。
- 所有外部 API 和 MCP 写操作具有 Scope、限流和审计。

## 17. 阶段完成定义

阶段 4 不以功能数量作为完成标准，而以平台是否形成稳定闭环判断：内容生产、人工审核、平台交付、数据回流、复盘建议和下一轮实验能够在同一项目体系中持续运行。
